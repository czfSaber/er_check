CHAPTER 0　/　通用

第 0 章通用方法

通用在任何一条排查命令之前，先把「此刻」固定下来。本章的四件事做错顺序，后面查到的东西都不能作为证据。

0.1　三条铁律　顺序不能颠倒

现场最常见的失误不是「没查到」，而是「查到了但证明不了」。以下三条按顺序执行，任何一条跳过都会让后续结论失去证据效力。

先快照，后分析把当前进程、网络连接、登录会话、内存中的命令行原样导出到只读介质。分析过程中的任何操作（包括打开文件、运行工具）都会改变系统状态。
先哈希，后复制对每个要提取的文件，先记录原始路径、大小、时间戳与 SHA256，再复制。复制件的哈希必须与原件一致，否则整条证据链断裂。
先留日志，后清现场日志是唯一能还原「攻击者做过什么」的记录。在确认日志已完整导出并校验之前，不要重启、不要清空、不要「顺手清理」。
本手册全部命令均为只读。唯一的写操作集中在第 7.5 节，且明确标注「取证之后再操作」。

0.2　证据固定的五个动作　每个动作都要留下记录

#动作做什么留下什么
1拍照屏幕全屏拍摄，包含任务栏时间、主机名、命令窗口标题照片编号 + 拍摄时间
2导出命令输出重定向到文件，不用「选中复制」文件名 + 大小 + 生成时间
3哈希certutil -hashfile（Win）/ sha256sum（Linux）SHA256 全串
4复制复制到只读介质，原件保持原位不动复制件路径 + 复制时间
5登记在证据清单中登记 1–4 的全部信息并签名证据清单（附报告首页）
# Windows：建立工作目录并导出第一份基线
mkdir D:\case
systeminfo > D:\case\01_systeminfo.txt
certutil -hashfile D:\case\01_systeminfo.txt SHA256 >> D:\case\00_hash.txt

# Linux：同样先建目录，再导出
sudo mkdir -p /mnt/case
ps auxf > /mnt/case/01_ps.txt
sha256sum /mnt/case/01_ps.txt >> /mnt/case/00_hash.txt
介质写入前先确认剩余空间：Windows dir D:\，Linux df -h /mnt/case。日志包动辄数百 MB，写满会导致导出中断且难以察觉。

0.3　提取样本的正确做法　只复制，不执行；只读打开，不双击

样本提取的目标是「可复核」，不是「能运行」。整个过程禁止双击、禁止用杀软扫描后隔离（会改变原文件），禁止上传到任何在线平台。

# Windows：先记录属性，再复制，再校验
certutil -hashfile "C:\path\suspect.exe" SHA256
copy /y "C:\path\suspect.exe" D:\case\samples\
certutil -hashfile "D:\case\samples\suspect.exe" SHA256

# Linux：用 cp -p 保留时间戳，复制后再校验
sha256sum /tmp/.x
cp -p /tmp/.x /mnt/case/samples/
sha256sum /mnt/case/samples/.x
情况做法禁止
文件正在被进程占用先记录进程 PID 与路径，用 copy /b 或 cp 尝试读取；失败则记录「被占用无法提取」不要 kill 进程后再取（会丢失内存证据）
文件已被删除但进程仍在记录 /proc/PID/exe 指向，Linux 可 cp /proc/PID/exe；Windows 记录句柄信息不要重启
文件极大（> 2GB）只提取头部 1MB 与尾部 1MB，并注明截断不要整盘复制
磁盘已满优先提取配置文件与小体积脚本，记录未提取清单不要删除任何现有文件腾空间

0.4　时间线与时间基准　所有判断都建立在「时间可信」之上

先确认三件事：主机时区、系统时间与标准时间的偏差、日志时间戳用的是本地时间还是 UTC。三者不确认，跨设备比对必然错位。

# Windows：时区与时间偏差
systeminfo | findstr /C:"时间" /C:"Time"
tzutil /g
w32tm /query /status

# Linux：时区、NTP 状态、当前时间
timedatectl
date -u; date
timedctl show 2>/dev/null | head -5

时间线表按「时间 / 来源 / 事件 / 证据位置」四列记录。同一事件若有多个来源（如文件 mtime 与登录日志），两行都记，互相印证。第 7.2 节给出模板。

文件时间可以被篡改（timestomp）。判定优先级：日志时间 > 文件 ctime > 文件 mtime。当 mtime 明显早于 ctime 且差值 > 1 秒时，应怀疑时间戳被改。
